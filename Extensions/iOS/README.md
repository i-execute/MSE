# MSE · iOS / iPadOS / macOS (Stay)

Userscript для Safari через [Stay for Safari](https://github.com/shenrui333/stay-for-safari) — расширение, которое
держит userscript-ы в Safari на iPhone, iPad и Mac.

## Что нужно

- Safari + Stay (бесплатная версия умеет один userscript — этого достаточно).
- Адрес шлюза от владельца: `https://<что-то>.ts.net` (tailscale) или свой адрес, если шлюз у вас свой.
- Ключ устройства: `mse_…` — его выдаёт панель расширения (кнопка `i` → «ключ»), вводить руками не надо.

## Установка (один файл, одна вставка)

Всё расширение — **один файл** `mse.user.js`: интерфейс, авторизация, мост к шлюзу и отладчик внутри одного
скрипта, отдельных частей для установки нет. Так же, как версия 0.2.

1. Поставьте Stay из App Store, включите его в **Настройки → Safari → Расширения**.
2. Скачайте `mse.user.js` (из `Storage/artifacts/` или из последнего релиза) и откройте файл — Stay предложит
   установить. Либо: Stay → `+` → **Install from file / URL**, один файл, одно поле.
3. Настройки Stay → ваш скрипт → **Allow**: `moodle.example.edu` (ваш Moodle), либо `*` если вам удобнее.
4. Откройте Moodle (`/my` или страницу попытки). Внизу справа появится пилюля **MSE**.

## Первый запуск

1. Тап по пилюле → панель. Если ответов нет — это нормально: база отвечает только на то, что знает.
2. Кнопка `i` → вкладка **шлюз** → вставьте адрес шлюза (`https://…`) → **проверить**.
   Адрес проверяется сразу: `/health` должен ответить `{"name":"MSE gateway"}`. Активная модель отображается в шапке, обновляется при проверке шлюза и по ответу агента; пока шлюз не назвал модель, чип скрыт.
3. Там же — `привязать к моему ID`: расширение само возьмёт Moodle ID и имя со страницы.
4. Владелец шлюза пускает ваш ID — после этого в панели появляется строка **AI**.

## Если что-то не так

| что видно | что делать |
|---|---|
| `нет данных страницы: ID пользователя` | открыть `/my` один раз; панель запомнит ID для этого сайта |
| `ключ не принят` | владелец не пустил ID: покажите ему свой ID из панели (`i` → аккаунт) |
| `шлюз не отвечает` | проверьте, что приложение tailscale подключено, и адрес скопирован целиком |
| пилюли нет | скрипт не разрешён для этого домена: Stay → скрипт → Allow |

## Обновление

Скачайте новый `mse.user.js` (один файл) и установите поверх: Stay заменит файл, настройки (адрес шлюза и ключ) сохранятся —
они лежат в localStorage страницы, а не в скрипте.

### Debug и Report

Откройте `i → AI gateway` и включите **Debug mode**: события расширения передаются владельцу шлюза автоматически. Выключатель сохраняется на сайте. На вопросе нажмите **Report**, чтобы отправить снимок независимо от режима Debug; **Snif → Copy** по-прежнему копирует локальную копию. Для отправки устройство должно быть зарегистрировано и одобрено.

Перед отправкой и на сервере удаляются ключ устройства, видимые значения cookie, скрытые и парольные поля, типичные токены, параметры URL и inline-скрипты. Однако универсально распознать произвольные секреты в тексте и HTML невозможно: дамп может содержать персональные данные. Используйте debug только с согласия пользователя и храните данные ограниченно. HTTP-заголовки загрузки и HttpOnly-cookie браузер скрипту не раскрывает. Для личной копии Snif проверяйте содержимое перед передачей.

Изображения передаются агенту как data URL только для доступных PNG/JPEG/GIF/WebP, ограничены размером; недоступные внешние изображения сообщаются как неподдерживаемые. Для сложных Moodle-плагинов и фактических тем нужна проверка на реальных данных.
