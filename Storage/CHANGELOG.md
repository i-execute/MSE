# Что менялось

## 2.3.0

- **Один каталог данных.** `state.json`, `admin-token.txt`, состояние туннеля и vault goygram живут в `/var/lib/mse`
  (режим 700, создаётся до старта юнитов). Больше нет `state not saved: ENOENT mkdir /opt/mse/data`, а обновление
  больше не уносит vault: код лежит в `/opt/mse`, данные — рядом с ним, но не внутри.
- **Настройки владельца переживают рестарт.** Квота, выставленная из панели, лежит в состоянии; раньше рестарт
  молча возвращал значение из окружения.
- **Адрес шлюза заменяется целиком.** Новый адрес пишется в оба хранилища, старый вычищается из всех мест
  (localStorage, хранилище расширения, зеркало, старый ключ), а сохранённым становится только проверенный адрес.
  Список того, что вычищено, попадает в журнал панели.
- **Воздух в панели.** Строки не липнут друг к другу, группы (адрес, связь, аккаунт, устройство) разделены и
  подписаны, шапка — это имя и одна тихая строка под ним. Ширина панели считается от экрана, тело ограничено
  по высоте, панель всегда внутри экрана.
- **Тема строго чёрно-белая.** Ни одного цветного пикселя: одна бумага, одна линейка, один акцент — белая рамка
  выбранной строки. Свечение осталось только на буквах «MSE». Системный шрифт, весь CSS — в одном файле
  `Extensions/src/theme.css`, старая тема удалена.
- **Туннель ждёт, а не падает.** `mse-tunnel.sh wait --timeout 60` после `funnel` и до рестарта роутера: повтор
  на `unexpected eof`/handshake/сертификат, понятная причина отказа.
- **Инлайн-режим проверяется при старте.** Если в BotFather он выключен — владельцу уходит строка в чат, то же
  видно в `self_check` и на панели; если сервер не ответил — тревоги нет.

## 2.2.0

- **Инлайн у бота заработал.** Результаты собирались в формате Bot API, а goygram отправляет инлайн по MTProto:
  теперь каждый результат — `inputBotInlineResult` с `send_message: inputBotInlineMessageText`, поэтому
  `messages.setInlineBotResults` больше не отвечает `nested object missing _`. Кнопка → поле → значение → тап
  снова применяет значение и удаляет сообщение-маркер.
- **Проверка inline при старте.** Бот спрашивает `getMe`, и если inline в BotFather выключен — пишет владельцу
  одну строку, кладёт её в журнал и в список проверок панели.
- **iOS — один файл.** Интерфейс, авторизация, мост и отладчик больше не создаются как отдельные `<script>` в
  рантайме: всё в одном файле, по изолированной области на часть. Сборка падает, если появится лишний скрипт,
  второй заголовок или `@require`; отчёт пишет `oneFile {scripts: 1, headers: 1, requires: 0}`.
- **Установка спрашивает ключи.** Первый запуск: bot token (3 попытки, формат), owner telegram id, tailscale auth
  key — всё валидируется, пишется в `/etc/mse/mse.env` (0600). Пайп без терминала получает точные команды.
  TUI «Install / Self-Heal» передаёт те же значения установщику и заранее пишет, чего не хватает.
- **Туннель и порядок старта.** `install → tunnel up + funnel → MSE_PUBLIC_URL → restart mse-router → проверка`:
  роутер больше не стартует с пустым адресом. В конце установщик печатает, активны ли оба юнита и есть ли адрес.

## 2.1.0

**Бот = панель OBHOD**

- Экраны собраны из `Rich` и уходят через `send_rich`/`edit_rich` — в чате настоящие заголовки, таблицы, чипы,
  разделители и ряд кнопок, а не текст с `<h2>` и `<tg-button>`. `Server/bot/ui.py` — порт `BOT/ui.py` и
  `BOT/icons.py` (пак tgiosicons, у каждой иконки есть unicode-запасной вариант), `Server/bot/screens.py` — сами
  экраны, `Server/bot/main.py` — роутинг кнопок.
- Экраны: панель, люди/заявки (разрешить, отклонить, отозвать), модель, квота, tailscale (up, funnel, serve,
  выключить), сервисы (перезапуск, стоп, старт, журнал), журнал, конфиг (секреты замаскированы, каждая строка
  меняется отдельно), обновление, помощь.
- Значение по кнопке: «type a name/number» — одно следующее сообщение становится значением; для `cfg:set:*`
  сообщение со значением удаляется из чата после записи в `/etc/mse/mse.env`.
- `tools/preview_rich.py` — прогнать все 14 экранов в личку владельцу (`--out` пишет HTML без сети, `--emoji` —
  с эмодзи-паком).

**Ввод значений — инлайн, как в обходе**

- Кнопка открывает поле сообщения с коротким подписанным токеном (10 символов, HMAC от «режим|поле|контекст»);
  владелец дописывает значение и тапает результат — значение применяется, сообщение-маркер удаляется. Так
  вводятся новый ключ tailscale, токен бота, owner id, api id/hash, Moodle ID (разрешить и отозвать), модель,
  квота. Чужой инлайн-запрос получает пустой ответ.
- Ключ tailscale после ввода сразу прогоняется через `mse-tunnel.sh up`, экран показывает результат.

**Эмодзи-пак из обхода — выключен по умолчанию**

- `Server/bot/icons.py`: весь набор `tgiosicons` (401 id + 61 именованный значок) с юникод-заменителями.
  `MSE_EMOJI=0` по умолчанию; включается кнопкой `emoji pack` на экране конфига или `MSE_EMOJI=1`.
- `<mark>`-заливки убраны совсем: чип — это тихий жирный синий текст, состояние — цветные слова и иконка.

**Проверка при старте**

- Бот при запуске проверяет настройки и связь с роутером и перечисляет, чего не хватает (admin token, owner id,
  токен бота, ключ tailscale, ответ роутера) — в журнал и одной строкой на панели.
- `tests/bot_selftest.py`: 14 экранов и 35 callback'ов — каждый рендерится как Rich, укладывается в 18 кнопок и
  64 байта данных, и на каждый кнопочный `data` находится обработчик.

**Установщик**

- Токен бота спрашивает сам установщик (шаг «bot token is required»), проверяет формат, до трёх попыток; без
  терминала — пишет точную команду `MSE_BOT_TOKEN=... bash install.sh`. Без токена бот не стартует, и в итоге
  об этом сказано прямо, а не «no bot token».
- Убран источник `sudo: 'obhod': command not found`: обратные кавычки внутри heredoc больше не исполняются.
- Юнит бота: `python -m bot.main` вместо `-m bot` и `HOME=/var/lib/mse` (при `ProtectHome=read-only` `/root`
  недоступен).
- После старта сервисов установщик до 15 с ждёт `curl 127.0.0.1:8788/health` и говорит, ответил ли роутер, а если
  нет — что смотреть (`journalctl -u mse-router`) и как перезапустить.

**TUI**

- Блочные заливки прогресса (`████`) убраны: шаг — галочка, название и короткая пунктирная линейка; работа идёт
  спиннером. Поле токена в «Model, Quota & Keys» помечено как обязательное, а сохранение без него предупреждает.

## 2.0.0

**Расширение**

- Два уровня доступа. Без регистрации (или пока заявку не приняли) — только строки их базы, к шлюзу **ни одного**
  запроса. После того как владелец пустил Moodle ID — там же строка **AI**: она появляется, когда база пуста,
  ответила ошибкой или тип задания не разбирается; текст растёт по мере ответа, тап ставит его в форму Moodle.
- Фикс полевого отчёта «нет данных страницы: ID»: ID ищется в `M.cfg.userid/userId/user.id`, затем в
  `data-userid`, ссылках на профиль, скрытых полях и в запомненном значении; если страница попытки не знает ID,
  панель один раз сама открывает `/my/` и берёт ID оттуда. Неполный запрос не уходит — панель называет, чего
  именно не хватает.
- Адрес шлюза вводится один раз и проверяется сразу (`/health` → `{"name":"MSE gateway"}`).

**Сервер**

- `mse-router.js`: приём снаружи, ключ устройства + allow-лист по Moodle ID, квота, журнал, прокси на локальный
  AI-бэкенд (`/v1/*`, стрим байт-в-байт). Ключ модели в роутере не живёт.
- tailscale вместо cloudflared: `mse-tunnel.sh` (`install/up/funnel/serve/off/status/url/wait`), стабильный адрес
  `<host>.<tailnet>.ts.net`, адрес сам попадает в `MSE_PUBLIC_URL`.
- `Storage/get.sh` + `Server/stack/install.sh`: установка одной командой, `/opt/mse`, `/etc/mse/mse.env` (600),
  `/var/lib/mse`, systemd-юниты, `sudo mse` (TUI).
- Telegram-панель на goygram: заявки устройств, `/allow`, `/approve`, `/revoke`, `/disallow`, квота, модель,
  журнал, включение/выключение funnel — кнопками и командами.

**Репозиторий**

- `scripts/audit.py --strict`: сканер отпечатков (токены, адреса, чужие пути, живые хосты) — обязательный шаг CI.
- Структура `Server/ · Extensions/{iOS,Android,Desktop} · Storage/ · scripts/ · tests/`.
