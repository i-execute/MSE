# Архитектура слоёв расширения MSE (layer.md)

Данный документ описывает внутреннюю структуру клиентского расширения MSE (`Extensions/src/`), назначение каждого компонента, потоки данных и правила для дальнейшей модификации кодовой базы без нарушения архитектурной целостности.

---

## 1. Обзор структуры файлов

```
Extensions/
├── src/
│   ├── theme.css            # Монохромные стили, анимации ауры и шиммера, подсветка
│   ├── mse-bridge.js        # Сетевой мост: взаимодействие с API шлюза (MSE Gateway)
│   ├── mse-ui.js            # Пользовательский интерфейс: пилюля, поповер, статус-бар, клики
│   ├── agent-prompts.js     # Форматирование контекста вопроса и системные инструкции AI
│   └── content.js           # Точка входа юзерскрипта, перехват и внедрение в DOM Moodle
└── tools/
    ├── repack-artifact.js   # Сборщик единого файла Storage/artifacts/mse.user.js
    └── build.sh             # Полная сборка с вендорскими исходниками
```

---

## 2. Назначение и ответственность модулей

### `Extensions/src/theme.css`
Файл отвечает за визуальный облик расширения в соответствии с концепцией **Single Dark Aesthetic**:
- **Цветовая палитра:** Глубокий темный фон (`#121214`), контрастный белый текст (`#f4f4f5`), приглушенные акценты (`#a1a1aa`, `#71717a`). Никаких лишних цветных рамок или кричащих градиентов.
- **Аура агента (`.agent-aura`):** Мягкое струящееся свечение вокруг статусной строки во время работы модели, анимированное через `box-shadow` без выхода за границы контейнера и без перекрытия соседних элементов.
- **Шиммер текста (`.agent-shimmer`):** Плавная анимация градиента по тексту активного действия («рассуждение», «анализ изображения», «запись ответа»).
- **Иконки действий (`.action-icon`):** SVG-иконки для трех фаз (мозг, глаз, карандаш).
- **Подсветка кликов (`.choice-row.lit`, `.choice-row.applied`):** Яркое визуальное свечение нажатого варианта ответа при переносе в форму теста.
- **Индикатор переподключения (`.reconnect-hint`):** Компактный блок под кнопкой агента с таймером обратного отсчета при ошибках 429 или 5xx.

### `Extensions/src/mse-bridge.js`
Сетевой слой, инкапсулирующий все обращения к серверному шлюзу:
- **`register(moodleId, name, site)`:** Регистрация устройства в шлюзе, сохранение ключа `mse_...` в `localStorage`.
- **`check()` и `quota()`:** Проверка доступности шлюза, получение текущего лимита дневной квоты, использованных запросов и времени до сброса в 00:00 UTC.
- **`askAgent(questionText, options, images, onChunk, onDone, onError)`:** Отправка вопроса в `/mse/v1/agent` с поддержкой потоковой передачи данных (Server-Sent Events, SSE).
- **Обработка ошибок:** Распознавание кодов ответа 401 (не авторизован), 403 (в ожидании одобрения администратора), 429 (исчерпана квота / Too Many Requests) и 5xx.

### `Extensions/src/mse-ui.js`
Слой графического интерфейса и взаимодействия с пользователем:
- **Пилюля MSE:** Плавающая кнопка для вызова настроек и отображения статуса шлюза.
- **Окно настроек (`viewGateway`):** Ввод адреса шлюза, проверка соединения, отображение статуса заявки и счетчика квоты (`quota: X/Y · resets after Xh Ym`).
- **Генератор иконок (`actionIcon(type)`):** Отрисовка векторных SVG-иконок мозга, глаза и карандаша.
- **Статусная строка агента (`appendAi`):** Рендеринг анимации рассуждения, стриминга ответа и блока автореконнекта с 5-секундным таймером.
- **Поповер вариантов ответа (`renderChoiceRows`):**
  - Поддержка множественного выбора (multi-answer): окно остается открытым после клика, позволяя выбрать несколько вариантов.
  - Мгновенный перенос выбранного значения в соответствующие чекбоксы или радиокнопки формы Moodle.
  - Активация яркой подсветки выбранного пункта.

### `Extensions/src/agent-prompts.js`
Модуль подготовки данных для языковой модели:
- Извлечение формулировки вопроса, таблицы вариантов и формул.
- Обработка встроенных изображений (приведение к допустимым размерам, base64-кодирование).
- Системный промпт, нацеливающий модель на выдачу строго структурированного ответа с указанием точных индексов верных вариантов.

### `Extensions/src/content.js`
Точка входа скрипта:
- Мониторинг загрузки страницы теста через `MutationObserver`.
- Обнаружение блоков вопросов Moodle (`.que.multichoice`, `.que.shortanswer`, `.que.match`, `.que.cloze` и др.).
- Внедрение элементов интерфейса MSE рядом с вопросом.

## 3. Жизненный цикл обработки вопроса в тесте

```
1. Загрузка страницы теста Moodle
   └─ content.js находит вопросы в DOM
   
2. Поиск ответа в локальной базе
   ├─ Ответ найден -> Подсветка правильного варианта
   └─ Ответ не найден -> Отображение кнопки вызова AI-агента
   
3. Нажатие пользователем кнопки агента
   ├─ Включение ауры (.agent-aura) и иконки рассуждения (Brain)
   ├─ mse-bridge.js отправляет POST /mse/v1/agent (SSE)
   ├─ Потоковый прием токенов ответа (Pencil / Eye)
   └─ Парсинг рекомендованных вариантов
   
4. Рендеринг поповера рекомендаций
   ├─ Отображение строк с вариантами
   ├─ Тап по первому варианту:
   │  ├─ Поповер остаётся открытым
   │  ├─ Чекбокс в тесте Moodle переключается
   │  └─ Строка варианта вспыхивает ярким свечением (.lit)
   └─ Тап по следующим вариантам (при множественном выборе)
```

## 4. Сборка и проверка целостности

Для сборки изменений в единый файл юзерскрипта используется утилита:

```bash
node Extensions/tools/repack-artifact.js
```

Скрипт собирает все компоненты в `Storage/artifacts/mse.user.js` и вычисляет контрольную сумму.

После внесения изменений обязательно запускаются автоматические проверки:
1. `python3 scripts/audit.py --strict` — проверка на отсутствие случайных приватных данных и соответствие стандартам;
2. `SS_BROWSER=webkit npm test` — полный прогон юнит- и E2E-тестов под WebKit.
