# Руководство пользователя и администратора MSE (версия 2.13.0)

MSE — это автономный комплекс для прохождения тестирования в системе дистанционного обучения Moodle, состоящий из клиентского расширения-юзерскрипта и серверного шлюза (Gateway).

---

## 1. Архитектура и принципы работы

Система MSE разделена на две изолированные части:

```
[ Браузер: Safari / Chrome / Firefox ]
       │  (HTTPS через туннель Cloudflared или Tailscale)
       ▼
[ MSE Gateway: mse-router.js ] ── /etc/mse/mse.env
       │  (локальный loopback 127.0.0.1:UPSTREAM_PORT)
[ Локальный AI-бэкенд ] ── OpenAI-совместимый API с ключом модели
```

### Ключевые преимущества безопасности:
- **Ключ модели никогда не передается клиентам:** Ключ хранится исключительно в локальном AI-бэкенде на сервере.
- **Двухуровневая авторизация:** Для доступа к шлюзу требуется подтверждение уникального ключа устройства (`deviceId`) и присутствие в `allow`-листе по Moodle ID.
- **Единый темный интерфейс (Single Dark Aesthetic):** Строгий монохромный дизайн без раздражающих разноцветных рамок и лишних элементов.

## 2. Клиентское расширение (Userscript)

Пользовательский скрипт `Storage/artifacts/mse.user.js` работает на всех платформах:
- **iOS / iPadOS:** Safari + Stay;
- **Android:** Firefox + Violentmonkey или Kiwi Browser;
- **Desktop:** Chrome / Edge / Firefox / Brave + Tampermonkey.

### Возможности расширения в версии 2.13.0:
1. **Множественный выбор ответов AI (Multi-Answer Selection):**
   - AI-агент анализирует вопросы с несколькими правильными ответами и рекомендует все подходящие варианты.
   - Поповер вариантов остается открытым до тех пор, пока пользователь не нажмет все нужные пункты.
   - Каждый клик по варианту мгновенно проставляет соответствующий чекбокс в форме Moodle.
   - Нажатый пункт подсвечивается ярким свечением (интенсивный белый glow), подтверждая применение.
2. **Переработанная статусная строка AI-агента:**
   - Убраны грубые рамки-обводки.
   - Добавлена мягкая переливающаяся аура (`agent-aura`), не перекрывающая соседние элементы DOM.
   - Мигающая точка заменена на 3 специализированные иконки состояний:
     - **Мозг (Brain):** этап рассуждения и логического вывода модели;
     - **Глаз (Eye):** анализ прикрепленных изображений и графиков;
     - **Карандаш (Pencil):** генерация и запись готового ответа.
   - Текст статуса сопровождается плавным переливающимся шиммером (`agent-shimmer`).
3. **Отображение дневной квоты:**
   - В карточке настроек шлюза отображается текущий остаток запросов (`quota: X/Y`) и точное время до сброса (`resets after Xh Ym` в 00:00 UTC).
4. **Умный автореконнект при ошибках (429 и 5xx):**
   - При превышении лимита или временной недоступности шлюза ошибка подробно логируется в консоль.
   - В интерфейсе под кнопкой агента появляется блок с предупреждением и 5-секундным таймером обратного отсчета до автоматического повтора запроса.

## 3. Серверный шлюз и панель управления `mse`

Шлюз устанавливается на сервер под управлением Linux (Ubuntu, Debian):

```bash
curl -fsSL https://raw.githubusercontent.com/i-execute/MSE/main/Storage/get.sh | sudo bash
```

### Меню TUI `sudo mse`:
Команда `sudo mse` открывает лаконичное интерактивное меню без дубликатов:
1. **Health & Status:** Полный статус сервисов (роутер, бэкенд, туннель, бот), текущая модель и адрес.
2. **Gateway Domain:** Управление публичным адресом шлюза:
   - **Cloudflared (Quick Tunnel):** Автоматически скачивает свежий бинарник с GitHub (с резервным закрепленным фолбеком), запускает туннель `*.trycloudflare.com` без необходимости ввода ключей и при смене адреса отправляет уведомление в Telegram-бот владельца.
   - **Tailscale (Funnel):** Позволяет использовать постоянный домен `*.ts.net`, запрашивая ключ аутентификации только по требованию.
   - **Turn off Tunnel:** Отключение активных туннелей.
   - **Status:** Просмотр активного режима и внешнего адреса.
3. **Install / Self-Heal:** Развертывание и восстановление файлов, виртуального окружения и systemd-сервисов.
4. **Service Control:** Управление юнитами `mse-router` и `mse-bot`, просмотр логов `journalctl`.
5. **Settings & Credentials:** Настройка модели, дневной квоты, токена бота и ID владельца.
6. **Uninstall MSE:** Безопасное удаление сервисов и бинарников или полная очистка данных.

## 4. Telegram-бот управления

Бот для владельца шлюза (`Server/bot`) обеспечивает полный контроль:
- **Карточки новых заявок:** Когда студент подключается к шлюзу, бот присылает сообщение с именем, Moodle ID, адресом сайта и инлайн-кнопками **Принять** и **Отклонить**.
- **Периодические уведомления об активности:** Бот ненавязчиво сообщает о прогрессе пользователей каждые N запросов (например: `👤 Иван Иванов (Moodle ID: 12345) выполнил 20 запросов к AI`).
- **Инлайн-настройка интервала:** В конфиге бота можно кликнуть **notify interval** и изменить шаг уведомлений (10, 20, 40, 50, 100 запросов).
